Two-Phase Polyglot Commit:
1. Reads user's staging_index rows + parent
commit's tree_nodes.
2. Computes Merkle tree_hash, commit_hash, and

3. Opens Postgres client: BEGIN → inserts trees &
tree_nodes → calls SELECT
fn_create_atomic_commit(...).
4. Opens Neo4j session: runs Cypher MERGE
(c:Commit {hash: $commit_hash})... MERGE
(c)-[:PARENT]->(parent).
5. If Neo4j succeeds → Postgres COMMIT. If Neo4j
throws → Postgres ROLLBACK (zero orphan state).

5.1 PostgreSQL Core DDL & CHECK Constraints (/database/postgres/01_schema_ddl.sql)
CREATE EXTENSION IF NOT EXISTS pgcrypto;
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL CHECK (char_length(username) >= 3),
    email VARCHAR(100) UNIQUE NOT NULL CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-
Za-z]{2,}$'),
    password_hash VARCHAR(255) NOT NULL,
    system_role VARCHAR(20) NOT NULL DEFAULT 'USER' CHECK (system_role IN ('ADMIN', 'USER')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE repositories (
    repo_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    repo_name VARCHAR(100) NOT NULL CHECK (repo_name ~ '^[A-Za-z0-9._-]+$'),
    description TEXT DEFAULT '',
    is_private BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(owner_id, repo_name)
);
CREATE TABLE repo_collaborators (
    repo_id UUID NOT NULL REFERENCES repositories(repo_id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    access_role VARCHAR(20) NOT NULL CHECK (access_role IN ('OWNER', 'MAINTAINER', 
'CONTRIBUTOR', 'VIEWER')),
    granted_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (repo_id, user_id)
);
CREATE TABLE blobs (
    blob_hash CHAR(64) PRIMARY KEY CHECK (blob_hash ~ '^[0-9a-f]{64}$'),
    content BYTEA NOT NULL,
    size_bytes BIGINT NOT NULL CHECK (size_bytes >= 0),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE trees (
    tree_hash CHAR(64) PRIMARY KEY CHECK (tree_hash ~ '^[0-9a-f]{64}$'),
    repo_id UUID NOT NULL REFERENCES repositories(repo_id) ON DELETE CASCADE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE tree_nodes (
    tree_hash CHAR(64) NOT NULL REFERENCES trees(tree_hash) ON DELETE CASCADE,
    file_path VARCHAR(512) NOT NULL CHECK (char_length(file_path) > 0),
    parent_dir_path VARCHAR(512) DEFAULT NULL,
    is_directory BOOLEAN DEFAULT FALSE,
    blob_hash CHAR(64) REFERENCES blobs(blob_hash),
    file_mode VARCHAR(10) NOT NULL DEFAULT '100644' CHECK (file_mode IN ('100644', '100755', 
'040000', '120000')),
    PRIMARY KEY (tree_hash, file_path)
);
CREATE TABLE staging_index (
    repo_id UUID NOT NULL REFERENCES repositories(repo_id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    file_path VARCHAR(512) NOT NULL CHECK (char_length(file_path) > 0),
    blob_hash CHAR(64) NOT NULL REFERENCES blobs(blob_hash),
    file_mode VARCHAR(10) NOT NULL DEFAULT '100644' CHECK (file_mode IN ('100644', '100755')),

// B. CREATE COMMIT & PARENT EDGES (Called inside Two-Phase Polyglot Commit)
MERGE (c:Commit {hash: $commit_hash})
ON CREATE SET c.repo_id = $repo_id, c.author_id = $author_id, c.message = $message,
              c.ci_status = 'PENDING', c.timestamp = $timestamp
WITH c
UNWIND $parent_hashes AS p_hash
MATCH (parent:Commit {hash: p_hash})
MERGE (c)-[:PARENT]->(parent);
// C. READ 1: BOUNDED DAG LINEAGE FOR NEXT.JS GRAPH CANVAS
MATCH (c:Commit {repo_id: $repo_id})
OPTIONAL MATCH (c)-[:PARENT]->(p:Commit)
OPTIONAL MATCH (t:Tag {repo_id: $repo_id})-[:TARGETS]->(c)
RETURN c.hash AS hash, c.message AS message, c.ci_status AS ci_status, c.timestamp AS timestamp,

ORDER BY c.timestamp DESC LIMIT 200;

6. "What Is Going On Under the Hood" — Viva & Live Demo Guide
Use these five core engineering explanations during your presentation and Viva so both teammates can
answer any conceptual or live-modification question from the evaluation panel:
1. Why Combine PostgreSQL, Neo4j, and pgvector? (Rubric #5 — Technology Justification): Relational
tables in PostgreSQL guarantee ACID transactions, foreign-key cascades, and fast byte-level
aggregations (SUM, GROUP BY, HAVING) for Content-Addressable Storage (blobs) and Role-Based Access
Control. However, finding the Lowest Common Ancestor (merge-base) across multi-parent merge histories
is a variable-depth graph pathfinding problem. Neo4j uses index-free adjacency (O(1) pointer hopping
along [:PARENT] edges), resolving criss-cross merge bases without expensive multi-level SQL self-joins.
Meanwhile, pgvector indexes 384-dimensional commit embeddings using an HNSW graph so users can
search commits by conceptual meaning rather than exact substrings.
2. How Does Content-Addressable Storage (CAS) Deduplicate Files? (Rubric #3 & #6): When a file is
staged, DB-Git hashes its raw bytes using SHA-256 to produce a 64-character hex primary key
(blob_hash) and executes INSERT INTO blobs ... ON CONFLICT (blob_hash) DO NOTHING. Even if the
same file is committed 20 times across 5 branches, physical bytes are stored only once in blobs, while
tree_nodes stores lightweight pointer rows. The view v_repo_storage_efficiency compares
SUM(DISTINCT size_bytes) against SUM(size_bytes) to display real-time storage savings.
3. Where Do SQL UPDATE/DELETE and NoSQL RUD Happen if Commits Are Immutable? (Rubric #6, #8 &
#9): Historical tables (blobs and commits) are locked by BEFORE UPDATE OR DELETE triggers
(prevent_historical_modification). Active SQL mutations occur on the working index (staging_index),
branch pointers (branches), and collaborator permissions (repo_collaborators). In Neo4j, while
[:PARENT] lineage edges are never altered, authentic Graph Updates (SET) modify CI build statuses

(c.ci_status) and re-point release tags (:Tag), and Graph Deletes (DETACH DELETE) prune unreachable
dangling commits via dbgit gc when experimental branches are deleted.
4. How Does the Two-Phase Coordinator Prevent Split-Brain State? (Rubric #8 & #11): During a commit,
the backend opens an explicit PostgreSQL transaction (BEGIN) and runs fn_create_atomic_commit(),
holding the transaction open while executing the Neo4j Cypher MERGE statement. Only after Neo4j
confirms the DAG edge write does PostgreSQL execute COMMIT. If Neo4j fails or times out, the API catches
the exception and issues ROLLBACK to PostgreSQL, ensuring PostgreSQL and Neo4j never drift out of
sync.
